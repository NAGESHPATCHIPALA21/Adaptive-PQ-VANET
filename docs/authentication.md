# Anonymous Authentication Protocol

## 1. Pseudonym Generation
To protect driver privacy and prevent tracking across RSUs, vehicles use an ephemeral or long-term pseudonym generated by the Trusted Authority:

$$\text{AID}_i = \text{"ANON-"} \,\|\, \text{HMAC}(\text{TA\_Key}, V_i \,\|\, \text{nonce} \,\|\, t_0)_{[0:16]}$$

The Trusted Authority securely archives $\text{AID}_i \leftrightarrow V_i$. Normal RSUs and neighboring vehicles interact solely with $\text{AID}_i$.

---

## 2. Mutual Challenge-Response Protocol

```
Vehicle (Vi)                           RSU / Fog Node
    │                                        │
    │ ─── 1. Challenge Request (AIDi) ─────> │
    │                                        │ Fresh nonce NR, timestamp tR
    │ <── 2. Challenge (NR, tR, Token) ───── │
    │                                        │
Compute response:                            │
Res = HMAC(Sec_i, NR || AIDi || tR)          │
    │                                        │
    │ ─── 3. Auth Response (AIDi, Res, tR) ─>│
    │                                        │ 1. Verify |t_now - tR| <= 60s
    │                                        │ 2. Check NR not in used cache
    │                                        │ 3. Verify HMAC response
    │ <── 4. Status: AUTHENTICATED ──────────│
    │                                        │
    │ <── 5. Unicast Session Key (SK-XXXX) ──│
```

---

## 3. Replay Protection & Freshness
Every challenge nonce is cached at the RSU with its generation timestamp. If a malicious node captures and attempts to replay `(NR, tR, Res)`, the RSU verifies that `NR` is already present in the active replay cache and immediately raises a `REPLAY_ATTEMPT` security alert, rejecting the vehicle and applying a trust penalty.
